#### 2026-02-20 - Separación Backend/Frontend
**Autor:** Kimi CLI  
**Archivos:** `server/index.js`, `AGENTS.md`

**Cambio:**
El backend ahora detecta automáticamente el entorno y solo sirve el frontend en producción.

**Motivación:**
- Evitar interferencias entre errores de frontend y backend
- Logs de consola separados y claros
- Hot reload más rápido en desarrollo

**Implementación:**
```javascript
const isProduction = process.env.NODE_ENV === 'production' || 
                     process.env.RAILWAY_ENVIRONMENT === 'production';

if (isProduction && fs.existsSync(clientDistPath)) {
    // Sirve frontend estático
} else {
    // Modo API-only
}
```

**Impacto:**
- Desarrollo más limpio y organizado
- Debugging más eficiente
- Preparación para deploy en Railway

#### 2026-02-18 - Sistema de Salarios Implementado
**Autor:** Kimi  
**Archivos:** `server/index.js`, `client/src/hooks/useWages.js`, `client/src/components/POSLayout.jsx`

**Feature:** Cálculo automático de salario de vendedores (5% de ganancia)

**Fórmula:**
```
Ganancia por Venta = Precio de Venta - Costo del Producto
Salario = 5% de la Ganancia Total
```

**Características:**
- Cálculo en tiempo real en el POS
- Salario acumulado entre sesiones (hasta que se pague)
- Solicitud de pago al enviar sesión a revisión
- Integración con Control de Efectivo
- Opción de redondeo para pagos

**Endpoints:**
- `GET /api/sessions/metrics` - Datos completos del turno
- `GET /api/wages/my-summary` - Resumen de salarios
- `POST /api/wages/request` - Solicitar pago
- `POST /api/wages/:id/pay` - Procesar pago (admin)
